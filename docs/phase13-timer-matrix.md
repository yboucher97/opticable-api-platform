## Retired development autonomy

optibrain-agent-dispatch.service/.timer, optibrain-agent-status.service/.timer and optibrain-agent-usage.service/.timer were independently disabled/inactive. No root/optibrain cron entry, queue dispatcher, controller.py/status.py/usage.py mailer process or startup hook was found running them. Installed code and authority files remain archival debt.

All six now require ConditionPathExists=/etc/optibrain/authorize-persistent-codex-development. That root-owned authorization file is absent. Enabling or invoking a unit cannot silently run its controller while the condition remains absent. Owner/admin root can deliberately change configuration; this is not protection against an authorized root rewriting units. Interactive Codex app-server/CLI processes are the manual workspace, not the retired dispatcher.

## Overlap and scalability

Three independently active Mail dispatchers exist: Cloudflare control-plane, combined GitHub lifecycle schedule and separate GitHub mailbox-poll schedule. Four current GitHub workflows have cron schedules, including separate owner digest and monitoring. Their source/idempotency identities differ, so core replay dedupe does not consolidate their reads. Assign one canonical scheduler in the next authorized mission. Digest HTTP acceptance can report success without an enabled workflow; combined wait loops can time out. These are containment side effects, not authority to re-enable drafts. GitHub also reports Validate Autonomous Core as ACTIVE metadata, but its workflow file is absent from current main: ORPHANED metadata, not evidence of a running persistent development worker.

Receipt polling re-reads known messages; lifecycle scans five modules; operator requests repeat scans. Long-running Phase 9/10 oneshots have no explicit timeout. Local backups lack an interprocess file lock and preservation disables nominal seven-generation pruning. These belong to P1/P2 remediation. Restore must first leave every writer timer disabled, reconcile all provider effects after the recovered generation, and selectively re-enable only safe read/backup timers and independently verified Test automation.

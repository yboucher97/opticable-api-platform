# Phase 9 intake and attribution foundation

The active AI evaluation page submits to `https://connect.opticable.ca/public/lead`. The main site's contact page embeds a Zoho Form; its CRM field mapping has not yet been proved end to end. The connector accepts the main site's Origin on the public endpoint, but that path is distinct from the embedded form. Direct CRM creation is another active route. Email/manual intake is not yet a verified automatic CRM intake route. Source is `Unknown` when evidence is missing; do not infer organic or direct traffic.

The connector already uses `Inquiry_ID` to reject exact submission replays and normalized email/phone/source ID to find an existing CRM identity. It preserves `First_*` attribution fields on a returning Lead and updates `Last_*`. `Ingestion_Source` describes the intake channel, while `First_Source`/`Last_Source` hold traffic source values from attribution. Zoho already has the needed source, campaign, medium, site, referrer, landing, and touch-time fields; no duplicate CRM fields are needed.

`workflow.automation.phase9_intake.IntakeLedger` records immutable, provider-reconciled Test Lab receipts in `phase9-intake.db` next to the automation DB. Its stable `OB-I-*` ID derives from source and `Inquiry_ID`. It stores an unambiguous UTC instant, submitted identity, canonical CRM ID, request hash, source details, provider action/version, and campaign context. Replaying the same inquiry and payload returns the same event; a changed payload under that ID fails closed. A new submission from the same identity gets a new event bound to the same Lead. Immutable `OB-F-*` feedback entries reference the first intake and carry Test Lab source to Lead/qualification/quote/opportunity outcomes. External ad conversion export is disabled.

The root-only manual Test Lab tool at `ops/phase9/test_lab_intake.py` writes an attempted-request journal **before** calling the active public endpoint. It preflights the protected CRM baseline and exact identity, never retries an attempted request, reads back `Inquiry_ID`, and marks a newly created Lead `OptiBrain_Test=true` before registering its receipt. The source trace is available to authenticated operators at `/v1/operator/phase9/source-trace/{lead_id}`. It requires the Lead in the root Test Lab registry, fresh Zoho readback, and the visible TEST_ONLY marker. The Phase 8 sales queue's Lab scope includes registered Phase 9 Leads with concise first/latest intake and campaign information; live scope excludes marked Phase 8 and 9 test Leads.

Root state: `/var/lib/optibrain/phase9/test-lab/registry.json`; protected baseline and ownership remain under `/var/lib/optibrain/phase8/test-lab/`. Production business actions and provider writes remain disabled. Only the manual root tool can use the Test Lab CRM grant. All operator-facing times use `America/Toronto`.

The connector does not yet automatically deliver every intake receipt to the OptiBrain ledger. The manual reconciliation tool establishes a provider-backed foundation and audit format; active-source event delivery should be the next bounded Phase 9 integration. The main Zoho Form mapping and external ad conversion uploads also remain unproved.

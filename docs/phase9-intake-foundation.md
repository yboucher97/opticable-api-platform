# Phase 9 intake and attribution foundation

The active AI evaluation page submits to `https://connect.opticable.ca/public/lead`. The main site's contact page embeds a Zoho Form; its CRM field mapping has not yet been proved end to end. The connector accepts the main site's Origin on the public endpoint, but that path is distinct from the embedded form. Direct CRM creation is another active route. Email/manual intake is not yet a verified automatic CRM intake route. Source is `Unknown` when evidence is missing; do not infer organic or direct traffic.

The connector already uses `Inquiry_ID` to reject exact submission replays and normalized email/phone/source ID to find an existing CRM identity. It preserves `First_*` attribution fields on a returning Lead and updates `Last_*`. `Ingestion_Source` describes the intake channel, while `First_Source`/`Last_Source` hold traffic source values from attribution. Zoho already has the needed source, campaign, medium, site, referrer, landing, and touch-time fields; no duplicate CRM fields are needed.

`workflow.automation.phase9_intake.IntakeLedger` records immutable, provider-reconciled Test Lab receipts in `phase9-intake.db` next to the automation DB. Its stable `OB-I-*` ID derives from source and `Inquiry_ID`. It stores an unambiguous UTC instant, submitted identity, canonical CRM ID, request hash, source details, provider action/version, and campaign context. Replaying the same inquiry and payload returns the same event; a changed payload under that ID fails closed. A new submission from the same identity gets a new event bound to the same Lead. Immutable `OB-F-*` feedback entries reference the first intake and carry Test Lab source to Lead/qualification/quote/opportunity outcomes. External ad conversion export is disabled.

The root-only manual Test Lab tool at `ops/phase9/test_lab_intake.py` writes an attempted-request journal **before** calling the active public endpoint. It preflights the protected CRM baseline and exact identity, never retries an attempted request, reads back `Inquiry_ID`, and marks a newly created Lead `OptiBrain_Test=true` before registering its receipt. The source trace is available to authenticated operators at `/v1/operator/phase9/source-trace/{lead_id}`. It requires the Lead in the root Test Lab registry, fresh Zoho readback, and the visible TEST_ONLY marker. The Phase 8 sales queue's Lab scope includes registered Phase 9 Leads with concise first/latest intake and campaign information; live scope excludes marked Phase 8 and 9 test Leads.

Root state: `/var/lib/optibrain/phase9/test-lab/registry.json`; protected baseline and ownership remain under `/var/lib/optibrain/phase8/test-lab/`. Production API business-action flags and unrestricted provider writes remain disabled. Only manually invoked root tools can use the Test Lab CRM grant. All operator-facing times use `America/Toronto`.

The connector does not yet automatically deliver every intake receipt to the OptiBrain ledger. The manual reconciliation tool establishes a provider-backed foundation and audit format; active-source event delivery should be the next bounded Phase 9 integration. The main Zoho Form mapping and external ad conversion uploads also remain unproved.

## Provider-backed Test Lab result

The checked-in ID snapshot is `ops/phase9/TEST_LAB_REGISTRY.json`; the root registry and immutable SQLite ledger are authoritative. Five distinct events cover a new AI Lead, same-source return, main-origin return, direct manual CRM creation, and unknown-source direct creation. An exact replay returned `duplicate_lead` and retained the original event ID. The three public submissions resolved to one Lead, `5062683000007898003`; first site/source and latest site/source remained distinct. The controlled Lead was then qualified with synthetic camera scope and linked by exact controlled email to a TEST_ONLY Contact. Zoho confirms Contact → Account → Deal relationships. The Deal `5062683000007913007` has no amount, Books transaction, or real revenue. The local audit contains `LEAD_CREATED`, `QUALIFIED_LEAD`, `QUOTE_READY`, and `OPPORTUNITY_CREATED` feedback events, all marked TEST_ONLY; external export is disabled. The Lead → Contact match is a suggestion, not a Zoho Lead conversion.

`OptiBrain_Test` now exists on Leads, Contacts, Accounts, and Deals. All registered Test Lab records in those modules have it set to `true` and carry the visible `OPTIBRAIN TEST — PHASE ...` marker. OptiBrain's live sales queue excludes these Leads and related identity suggestions, while Lab scope verifies the flag and ownership. Zoho native reports and views must filter `OptiBrain_Test is not true` to exclude synthetic counts. The Test Lab Deal has a null amount, so it contributes no revenue amount. The public connector's new Lead creation does not set the test flag immediately; the manual, journaled reconciliation sets it after provider readback. This brief interval is a limitation of public-route validation and is protected in OptiBrain's queue by the visible company marker.

One initial public request failed with Zoho `INVALID_DATA` on `Last_Touch_Time`; zero CRM records were found for that request. The connector now emits a numeric-offset, second-precision datetime, and a controlled CRM readback confirmed the format. A later successful public create exposed Zoho Search indexing delay: the public response and bounded CRM list/readback agreed, while Search briefly returned no match. The Test Lab tool now reconciles from a complete bounded list and waits for Search convergence before a returning submission. The failed attempt remains in the root registry and was never blindly retried. The connector's source-scoped ID repair was also tested against a real Test Lab Lead with a colliding source record ID in a no-write public dry run; it returned `would_create_lead` and left the existing Lead unchanged.

# Phase 9 intake and attribution foundation

The active AI evaluation page submits to `https://connect.opticable.ca/public/lead`. The main site's French and English contact pages embed separate Zoho Forms. A controlled French form submission proved Form → Zoho Mail notification → Zoho Lead creation; the provider's mapping omitted Email and all source fields. OptiBrain's read-only collector now preserves the authenticated notification and reconciles a unique CRM candidate using name, company, phone, and creation time. Missing email is shown for review. The English form's published labels are supported by focused parsing tests, but it has not received a controlled provider submission. Direct CRM creation is another active route. Email/manual customer-mail-to-CRM intake is not verified. Source is `Unknown` when evidence is missing; do not infer organic or direct traffic.

The connector already uses `Inquiry_ID` to reject exact submission replays and normalized email/phone/source ID to find an existing CRM identity. It preserves `First_*` attribution fields on a returning Lead and updates `Last_*`. `Ingestion_Source` describes the intake channel, while `First_Source`/`Last_Source` hold traffic source values from attribution. Zoho already has the needed source, campaign, medium, site, referrer, landing, and touch-time fields; no duplicate CRM fields are needed.

`workflow.automation.phase9_intake.IntakeLedger` records immutable, provider-reconciled Test Lab receipts in `phase9-intake.db` next to the automation DB. Its stable `OB-I-*` ID derives from source and `Inquiry_ID`. It stores an unambiguous UTC instant, submitted identity, canonical CRM ID, request hash, source details, provider action/version, and campaign context. Replaying the same inquiry and payload returns the same event; a changed payload under that ID fails closed. A new submission from the same identity gets a new event bound to the same Lead. Immutable `OB-F-*` feedback entries reference the first intake and carry Test Lab source to Lead/qualification/quote/opportunity outcomes. External ad conversion export is disabled.

The root-only manual Test Lab tool at `ops/phase9/test_lab_intake.py` writes an attempted-request journal **before** calling the active public endpoint. It preflights the protected CRM baseline and exact identity, never retries an attempted request, reads back `Inquiry_ID`, and marks a newly created Lead `OptiBrain_Test=true` before registering its receipt. The source trace is available to authenticated operators at `/v1/operator/phase9/source-trace/{lead_id}`. It requires the Lead in the root Test Lab registry, fresh Zoho readback, and the visible TEST_ONLY marker. The Phase 8 sales queue's Lab scope includes registered Phase 9 Leads with concise first/latest intake and campaign information; live scope excludes marked Phase 8 and 9 test Leads.

Root state: `/var/lib/optibrain/phase9/test-lab/registry.json`; protected baseline and ownership remain under `/var/lib/optibrain/phase8/test-lab/`. Production API business-action flags and unrestricted provider writes remain disabled. Only manually invoked root tools can use the Test Lab CRM grant. All operator-facing times use `America/Toronto`.

Phase 9 Mission 2 added a five-minute, read-only receipt collector. The connector stores a replay-stable acknowledgement under a source/inquiry/request hash and exposes it through a dedicated read-only credential. The collector appends those acknowledgements and authenticated Zoho Forms Mail notifications to immutable SQLite tables in `phase9-form-receipts.db`. Exact provider replays create one row; a conflicting payload under the same inquiry ID fails closed. The connector secret is derived in the deployment workflow and delivered to the VPS encrypted with the public key in that workflow; only the root private key and service-readable secret file reside on the VPS. The timer invokes Python only and has no Codex/autonomous-development role. Source trace and Lab sales queue read the resulting chronology. The older Test Lab-only `phase9-intake.db` remains for historical feedback events.

The active French Form's native CRM mapping currently omits Email, `Ingestion_Source`, and first/latest touch. The controlled Form-created Lead `5062683000007935001` was matched read-only by the collector and then repaired **only because it is a new registered TEST_ONLY record**. Production customer records receive no automatic patch. The operator receipt view at `/v1/operator/phase9/intake-receipts` shows any missing mapping for review. Fixing the Zoho Forms integration's native field mapping is the remaining production attribution gap; do not assume form-created customer Leads are deduped by email until its mapping is corrected and revalidated.

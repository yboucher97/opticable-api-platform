# Universal owner Decision Card

AUTHORITATIVE CURRENT CONTRACT. This extends the existing Optimization Proposal, Business Priority, shared journal and Manager. It creates no second proposal store, production executor, authority, observer scope or foundation phase. Release receipts establish when the implementation is live.

Every owner-facing proposal and meaningful change requires an explanation: website/SEO/Forms, Ads, content, reply/outreach drafts, CRM, automation/system/provider configuration, customer expansion, recurring revenue, tenders, business priorities, technical optimization, data repair and deployment. The central store validates the reusable projection at ingestion and exposes it on all proposal/priority reads. Explicit authored cards may extend schema-1 records or their existing detail. Legacy immutable records receive a derived card without altering their hash, revision, rejection suppression or approval binding.

Cards begin WHAT CHANGED, WHY, MAIN BENEFIT, MAIN DOWNSIDE, RECOMMENDATION. They require current state, exact proposed change, concrete reason, evidence, pros, cons, risks, expected benefit, observed facts, tested facts, hypotheses, inferences, unknowns, HIGH/MEDIUM/LOW confidence with reason, do nothing, rollback, recommended APPROVE/REVISE/REJECT/DEFER with reason, all four owner options and dependencies. Manager shows the concise summary, pros/cons and confidence before expansion. Exact comparisons are escaped and never shortened. Domain proposal-detail routes use the same presentation. Owner DEFER maps to the existing WAIT journal state; execution authority remains separate.

Content/configuration changes require exact BEFORE/AFTER when observed. Missing current text is UNKNOWN, never reconstructed from a proposed draft. Preparation requires exact source replacements against the base; a no-op capability verification is permitted only for a canonical SITE_PREVIEW_VERIFICATION with no_op=true, matching base SHA and empty files/changes. No-op source head must equal the base. No marketing edit or empty Git commit is fabricated.

Technical cards carry repository, base/proposal SHA, changed files, test receipts, preview URL, production impact, rollback reference, stale state, affected provider configuration and indirect changes. Unknown metadata stays visible; a stored PASS flag or an old hosted URL does not override current exact-head readiness. Only passing checks for the current head are tested facts. Business benefit remains EXPECTED/HYPOTHESIS until measured. Exact website approval and stale receipt checks retain their original guards.

Measurable proposals retain the existing baseline/metric/window/success/guardrail plan, plus result state. Actual business learning requires before state, production execution tuple and receipt, after state, metric result, comparison windows, outcome, learning, evidence and limitations in existing manager_learning. Preview, owner approval and TEST receipts cannot establish a production result. Existing legacy learning remains readable. Nothing here executes a production change.

Automatic todos remain Business Priorities. Each carries why it exists, latest authoritative event or explicit observed state/evidence, required action, real deadline only, consequence of ignoring it, confidence and exact proposal/priority linkage. Ready preview requests review; revision requests prepare revision; provider failure requests verification; approved preview waits for separate production authority; rejection/defer suppress repetition under the existing semantic evidence rules. Commercial lifecycle precedence remains authoritative.

The camera example recommends REVISE: keep useful technical scene-design detail while making commercial/local intent and the quote CTA clear. It discloses lost specificity, subtle change and unproven conversion lift. [Implementation and site registry](decision-cards-multisite/implementation.md) describe the controlled verification. No website merge, production website upload, DNS, customer send, Ads, CRM or Books mutation is authorized by a card.

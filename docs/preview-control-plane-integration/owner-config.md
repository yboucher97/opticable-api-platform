## Cloudflare reads and isolated target

Trigger discovery is `GET /accounts/{account_id}/builds/workers/{external_script_id}/triggers`; use the immutable Worker tag, not its name. The API explicitly accepts **Workers CI Read** (write is unnecessary for discovery). [Trigger API](https://developers.cloudflare.com/api/resources/workers_builds/subresources/triggers/methods/list/). The current Builds guide requires a **user-scoped API token**; account-scoped tokens return Invalid token. Its UI uses Workers Builds Configuration terminology for configuration editing; do not substitute Edit authority for this read-only mission. The old401 does not establish whether the token type or scope caused rejection. Owner must supply a user-scoped token with effective read permission and prove one bounded200 read; stop on401/403. Add Workers Scripts Read only for Worker-tag/source discovery when needed. [Builds token requirements](https://developers.cloudflare.com/workers/ci-cd/builds/api-reference/).

Recommended target, subject to name/ownership verification: owner pre-provisions **opticable-optimization-preview**, a separate Worker with static assets, no production routes/custom domains, production secrets or production writable bindings. Use read-only Worker metadata/content access for discovery/status. For later uploads, a separate principal gets **Editor on that one existing Worker**; keep provisioning/deletion Admin outside runtime. Current Cloudflare roles support selected-Worker scopes. If the account/API token cannot enforce that boundary, use a dedicated preview account before writes. Do not grant Zone Workers Routes Write, DNS write or production Worker Editor. [Worker roles](https://developers.cloudflare.com/workers/authorization/workers/).

Enable Version URLs on the isolated Worker only. Immutable version URL format: `<version-prefix>-opticable-optimization-preview.<verified-account-subdomain>.workers.dev`; record the actual exact hostname in the allowlist after provisioning. An alias can aid navigation but the immutable version ID/URL controls verification. Version URLs reuse a Worker's configuration/resources, so a production Worker's version URL is insufficient isolation. [Version URLs](https://developers.cloudflare.com/workers/versions-and-deployments/version-urls/).

Future pinned preview-only policy uploads one version to the isolated target, with tracking disabled, noindex, canonical production-origin page URLs and no native Forms submission. Include a nonsecret `/preview-evidence.json` manifest containing proposal ID/revision, repository, base/head SHAs, branch and artifact hash. Bind provider version metadata and HTTP manifest to the exact full head SHA. No production deployment/route change is permitted. Keep at most one initial camera version/three active proposal worktrees, a bounded build timeout/read budget and an owner cost/retention limit; later teardown requires an explicit reviewed sequence. Budget alerts alone are not a hard spending cap.

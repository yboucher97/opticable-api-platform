# Phase 8 provider-backed Test Lab

The authenticated sales queue has two read-only scopes:

- `/v1/operator/phase8/sales-queue` shows the live CRM sample and excludes every Lead with `OptiBrain_Test=true` or the visible `OPTIBRAIN TEST — PHASE 8` description marker.
- `/v1/operator/phase8/sales-queue?scope=lab` shows only IDs in the root-owned Test Lab registry, after checking the provider marker on every Lead. This is synthetic data, not a customer pipeline. Simulated source categories are labelled as such.

The CRM baseline was captured before the first Test Lab write. The canonical protected inventory is `/var/lib/optibrain/phase8/test-lab/PROTECTED_PREEXISTING_RECORDS.json`, with a checked-in historical copy at `ops/phase8/PROTECTED_PREEXISTING_RECORDS.json`. It protects 11 Leads, 45 Contacts, 41 Accounts, one Deal and one Task, plus the empty Calls, Notes and Events modules. Zoho's `Meetings` API name is invalid in this account; the supported module is `Events`. The prior controlled Lead `5062683000007880001` and its prior Task are protected. No pre-existing CRM record was mutated during this mission.

`/var/lib/optibrain/phase8/test-lab/registry.json` is the root-only ownership ledger. A checked-in snapshot is `ops/phase8/TEST_LAB_REGISTRY.json`; `/etc/optibrain/phase8-test-lab-registry.json` is a minimal group-readable projection used by the API. Root-only create/update scripts journal an attempted operation before transport, never blindly retry an ambiguous result, and verify provider readback. The exact-call CRM boundary checks the immutable baseline hash, target ownership, relationship targets, visible marker, allowed synthetic/operator-controlled email addresses, root identity, and a process-local single-use grant. The production API user cannot activate this boundary. A protected Lead PUT dry run is denied before transport; an owned Lead PUT dry run is allowed.

Zoho Leads gained three non-duplicate fields: `OptiBrain_Test` (boolean), `Scope` (text), and `Project_Timeline` (text). The latter two repair a quote-readiness gap: the previous queue expected fields that were absent in CRM. Filter `OptiBrain_Test is not true` in Zoho reports, views, marketing and revenue metrics. Do not use Test Lab email addresses for customer outreach.

The nine synthetic Leads cover urgent cabling, a Wi-Fi quote, overdue access control, waiting cameras, a controlled reply path, incomplete discovery, early research, and an exact-email duplicate pair. The registry records provider IDs, email identities, expected classification/action, Tasks and relationship records. One Account, Contact and Deal form a verified Contact→Account→Deal chain; the corresponding Lead match remains a **suggestion**, not a provider-linked Lead conversion. Three Tasks represent past and future obligations. Two Test Lab outbound messages were sent once from `yboucher@opticable.ca` to operator-controlled addresses and verified in Zoho Sent.

On September 30 at 8:20 PM EDT, one controlled reply was sent from the verified `info@opticable.ca` alias to `yboucher@opticable.ca` using Zoho Mail's reply action on the inbox copy of outbound `1790811285655138300`. The inbound copy is `1790814018711152600`; its `In-Reply-To` and `References` headers match the outbound Internet Message-ID. The Sent copy is `1790814016763138300`. The root registry records these IDs and the at-most-once reply journal is `/var/lib/optibrain/phase8/test-lab/phase8-closure-reply-journal.json`. The alias and primary address share one Zoho mailbox, so this proves provider-backed receipt and threading within that mailbox, not delivery between independent providers. Gmail search remained unavailable and was not required.

The queue reads bounded CRM lists and exact Test Lab Sent messages, checks inbound thread headers, and uses aware instants with `America/Toronto` display. It ignores a shared mailbox's Sent copy when classifying incoming mail, while requiring an actual Inbox copy with matching reply headers. The live scope checks Mail only for the original controlled Lead and marks other inbox states unverified. Drafts in the queue are previews only; no provider send or draft-save endpoint is attached. A linked reply suppresses generic follow-up, raises the reply-path Lead to HIGH, displays new reported project details and a contextual unsent draft, and marks reply-supplied scope for human verification before quoting. WAIT suppresses duplicate outreach, ambiguous Mail identity suppresses suggestions to send, and duplicate Leads require manual review. Quote readiness requires open status plus service, site, scope and timeline. Age alone does not raise priority. A past open Task plus an elapsed deadline and no evidenced contact can be neglected; a completed Task removes that label.

Provider transition evidence is in `/var/lib/optibrain/phase8/test-lab/transition-journal.json`: removing the synthetic quote Lead's scope changed READY FOR QUOTE to NEEDS INFORMATION; restoring scope restored readiness. Completing the synthetic overdue Task removed NEGLECTED; reopening it restored the label. The registry and readback journals remain available for future Phase 9–12 regression. Only Test Lab records may be changed in later test missions unless the owner explicitly authorizes another target.

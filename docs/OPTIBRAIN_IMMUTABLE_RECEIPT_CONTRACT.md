# Immutable Forms receipt contract

AUTHORITATIVE CURRENT — API 1.24.1 patch.

Zoho Forms receipts live in `phase9-form-receipts.db`. The event ID is the existing `event_id("zoho_form", Internet Message-ID)` digest. Event ID, provider message ID and Internet Message-ID are each unique. The authenticated mailbox is fixed; folder/read flags are mutable lookup metadata, never receipt identity. Receipt evidence includes the original body SHA256, form identity, received time, parsed native facts and captured attribution. Identity semantics and original content are unchanged.

`form_receipts` UPDATE/DELETE triggers remain mandatory. EXACT_REPLAY means identical canonical evidence, or an explicitly bounded deterministic projection from the same provider body and unchanged original facts. Only missing language derived from the known FR/EN form ID, missing empty attribution, the established controlled TEST_ONLY exclusion, and the existing strict inline acquisition-context projection are permitted. These additions are immutable `form_parse_projections`, `form_test_classifications` or `form_context_projections`; they never replace original evidence. Original and derived evidence remain separately accessible. No changed body/hash, native field, identity, timestamp or attribution is normalized away.

A genuine mismatch raises `ImmutableReceiptConflict`. The collector records immutable `form_message_anomalies` with account/message identity, original event reference, new canonical evidence/hash, reason and observed time. Each evidence variant has a deterministic unique ID; repeated identical conflicts reference the same anomaly. Snapshot storage is capped at128KiB; larger payloads retain their hash/size and original provider-message reference. Anomalies expose no personal data in operator health. Existing receipts, journals, links, Mail messages and attribution are never deleted or overwritten. Quarantined receipts are excluded from CRM matching and form enrichment until a separately reviewed resolution policy exists; this patch adds no resolution/write authority.

The pre-existing failure was parser representation drift, not changed Mail content: one Phase16 controlled receipt lacked newer `language`/empty `attribution` fields and had the old TEST_ONLY flag. A byte-comparison of provider identifiers/body and every unchanged native fact establishes the replay. Scheduler overlap or duplicate delivery did not have to be assumed.

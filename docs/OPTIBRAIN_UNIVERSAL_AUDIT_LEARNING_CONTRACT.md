# Universal action evidence and continuous learning

AUTHORITATIVE CURRENT. Post-foundation capability extension, API 1.34.0. This contract applies to current and future OptiBrain features. No evidence record grants provider authority. The existing root policies, protected identities, fresh off-host effect claims and exact release gate remain authoritative. Customer authority stays CLOSED; its timer stays DISABLED. Camera revision 4 remains REVISE with superseded preview proof; AI accessibility failure remains blocking. Neither preview is outcome learning.

## Storage and execution

`action_evidence.py` extends the existing `action_envelopes` and hash-chained, append-only `action_evidence` tables. Existing BusinessJournal envelopes and hashes remain intact. Scoped lifecycle/provider receipts retain their original references; the universal envelope supplies a common projection over the same action ID. Workflow orchestration evidence uses its existing automation database; business/proposal/preview/learning evidence uses the existing phase12-autonomy database. No additional database, timer, authority policy or provider writer is introduced.

Every meaningful action has an immutable action ID and plan, source/target identities, exact versions, approval requirement and record, before/proposed/actual-after states, reproducible concise rationale, evidence/rules/pros/cons/risks, expected benefit/downside/confidence, facts/inferences/hypotheses/unknowns, alternatives/dependencies, technical request/response summaries, readback, measurement/baseline, rollback/compensation, final result and learning linkage. Uncollected fields stay explicitly unknown. Private model reasoning is rejected. The machine-readable [envelope schema](optibrain-action-evidence.schema.json) and validators are mandatory for new adapters.

Four logical layers share that journal: TECHNICAL_AUDIT, BUSINESS_EVENT, DECISION and RECOVERY. Plans precede consequential transport. Provider success alone cannot finish an action: actual read-after-write must verify the expected state. A provider without readback must be explicitly classified as unsupported and its specific limitation recorded; the result distinguishes acknowledged-with-limitation from verified. Safe failure evidence retains stage, error class, status, partial-effect uncertainty and reconciliation/cleanup procedure. Ambiguous effects are not replayed automatically.

The existing opt-in Sales draft adapter resolves the native Drafts folder before writing and reads exact message metadata/content afterward, using Zoho's [folder](https://www.zoho.com/mail/help/api/get-all-folder-details.html), [metadata](https://www.zoho.com/mail/help/api/get-email-meta-data.html) and [content](https://www.zoho.com/mail/help/api/get-email-content.html) APIs. It persists hashes rather than draft bodies. Each revised draft receives its own audit identity; mismatched readback requires reconciliation. Conversion exports remain OFF; any later authorized upload remains pending until native destination diagnostics verify one processed event, without claiming Ads attribution.

Reversibility is FULLY_REVERSIBLE, REVERSIBLE_WITH_LIMITATIONS, COMPENSATING_ACTION_ONLY, IRREVERSIBLE or UNKNOWN. UNKNOWN blocks mutation. Reversible mutations require an exact rollback target/procedure before execution. Email sends, irreversible conversion, payment/legal acceptance/destructive deletion and consumed publication require an explicit consequence, compensation assessment and higher exact approval boundary. The existing delegated root scope is disclosed as delegated authority, never a newly clicked human approval. No Books writer is authorized. A rollback has a distinct action ID, original link, restored-state expectation, actual readback and result; original history is never erased.

Approvals bind the immutable action revision and full before/proposed values plus exact SHA/config/object/draft versions, test and preview evidence. Material proposal changes invalidate execution even if an older action approval remains retained. Local Manager approval is intent only. Automatic actions record the existing authority class/rule, before/after/readback and recovery classification. Future external adapters must call `execute_action` with a separate trusted authority check and provider acknowledgement/readback/verification callbacks. The audit contract never replaces transport authorization.

## Multi-source proposals

Material optimizations use relevant available evidence, rather than indiscriminately requiring every provider. The existing Manager observer performs bounded exact page/native-object reviews of cached Search Console, GA4, Forms, CRM, Books, Mail and research context. It persists dated evidence bundles in the existing action journal. Sources without inspectable target evidence are explicitly UNAVAILABLE/UNKNOWN; unrelated account/session aggregates are not promoted into source attribution. Provider caches are reused, with zero additional provider/model calls.

Each item records source, original source date, observation date, freshness, completeness, proposal relationship, evidence reference and DIRECT/SUPPORTING/CONTEXT/COUNTEREVIDENCE/UNKNOWN class. OBSERVED, TESTED, MEASURED_RESULT, INFERENCE, HYPOTHESIS and UNKNOWN are canonical proof classes; legacy source terms are projected without rewriting old revisions. Counterevidence review retains limitations and contradictory observations, the searched source inventory and unresolved performance/quality/seasonality/source-mix/tracking/concurrent-change checks. A missing source or tiny sample remains a limitation. Competitor practices are context, not performance proof or permission to copy wording.

Bounded native joins attempt query → page → campaign → session → inquiry → Lead → Deal → Estimate → Invoice → measured revenue. Relationship strengths are DETERMINISTIC, STRONGLY_SUPPORTED, WEAKLY_SUPPORTED or UNKNOWN. The current automatic joiner emits DETERMINISTIC only for evidenced native IDs and WEAKLY_SUPPORTED for aggregate page relationships. A connected evidenced path is required for deterministic business lineage. No fuzzy email/company/date/amount join can establish acquisition. A deterministic lineage still does not prove that a content change caused an outcome. gclid/gbraid/wbraid and UTM context can supply source evidence where the existing attribution contract establishes their provenance; missing session/inquiry links remain unknown.

## Measurement and reusable learning

Every measurable execution freezes a pre-execution baseline including exact production version, proposal/entity, timestamp, source-dated metrics, traffic mix, qualified business outcomes and tracking completeness. The execution gate requires a primary metric, secondary metrics, guardrails, window, evidence sufficiency requirement and attribution limits, plus a reviewed evidence bundle. It rejects a changed canonical proposal/hash or mismatched production baseline. Sparse volume has no invented significance threshold.

Canonical Learning Records extend `manager_learning`; no competing learning store is created. Each record binds an actually verified production action/proposal revision, site/service/language/audience/channel/change class, frozen baseline, dated after evidence, result, confidence factors, confounders, limitations, concise lesson and reuse eligibility. Results are POSITIVE, NEGATIVE, MIXED, INCONCLUSIVE or NOT_MEASURABLE. Confidence accounts for sample size/duration/completeness/tracking/seasonality/source changes/simultaneous changes/repeatability/business relevance. Unknown factors lower confidence; measured result classifications must agree with the comparison. Previews, approval intent and unsourced legacy prose cannot manufacture reusable outcomes.

Retrieval includes supporting and negative/counterevidence outcomes with exact site, service, FR/EN, audience, channel and change-class isolation. SITE-SPECIFIC, SERVICE-SPECIFIC, AUDIENCE-SPECIFIC, CHANNEL-SPECIFIC and GENERALIZABLE are recorded; generalized classification requires transfer evidence and never silently permits cross-site reuse. Inconclusive lessons remain context with reuse_eligible=false. Learning can refine recommendations/ranking/confidence/content/channel strategy. It cannot edit authority, financial/destructive/approval/security/rollback safeguards; no learning path writes these policies.

## Owner views and todos

Decision Cards show why, dated sources, counterevidence search/findings, canonical proof classes, previous relevant learning, expected result, measurement, rollback and a durable audit ID. Legacy immutable records receive an honestly dated observation through the existing observer; historical execution is UNKNOWN. Cards remain viewable before that observation and disclose pending audit linkage. The current camera card remains REVISE and has no measured result/learning.

The existing Manager view includes a chronological action timeline. Authenticated GET `/v1/operator/manager/audit` accepts bounded text, status, since, automatic and limit filters; it is private/no-store and grants no execution. It supports change/automatic/approval/failure/recovery/outcome searches by action/proposal/target/rationale.

Todo transitions are append-only local effects: CREATED, UPDATED, SUPPRESSED, COMPLETED or REOPENED, with underlying/latest event, Decision Card/proposal/priority IDs, evidence, actionability and reason. Completion requires explicit completion evidence; disappearance alone records suppression, not invented completion. Reopen gets a distinct linked transition even when its content equals an earlier state. Unchanged observer passes deduplicate without creating telemetry noise.

## Future email, document and financial intelligence

The [future payload schema](optibrain-intelligence-evidence.schema.json) and `future_intelligence_contract` prepare message/thread/sender/classification/confidence/reason/original-new labels/attachment hashes/destination/business entities/owner correction/undo references; file moves preserve original/destination/hash and restoration/removal procedure. Financial matching separates observed document, Books candidate, bank candidate, amount/date/reference, client/vendor/project and DETERMINISTIC/HIGH_CONFIDENCE/POSSIBLE/UNKNOWN match strength. books_mutation=false is required. This release does not build mailbox/document ingestion, classification automation, file moves or financial mutations.

## Retention and sensitive evidence

Consequential provider mutations, finance, communications, contracts, deployments, authority changes and recovery records are durable and never automatically purged. Financial/contract evidence receives a minimum seven-year retention review horizon, extended for legal holds and applicable owner policy; this is a retention policy, not automatic deletion authority. Immutable effect identity, deduplication and recovery links remain durable beyond any summary. Snapshot evidence uses bounded references/hashes when raw source data is unsuitable. Existing noisy metrics/cache retention stays 30 days with aggregate summaries; unchanged source/priority states are deduplicated. No indefinite raw per-read telemetry is added.

Recursive redaction strips tokens/API keys/passwords/private keys/auth headers/cookies/credential-bearing URLs and environment-bound secret strings; safe identifiers/hashes remain. Audit API responses remain owner-authenticated and private. See [state](OPTIBRAIN_STATE_CONTRACT.md), [deployment](OPTIBRAIN_DEPLOYMENT_GUIDE.md) and [recovery](OPTIBRAIN_RECOVERY_GUIDE.md) for original execution authority and preservation contracts.
